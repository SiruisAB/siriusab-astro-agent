# 技术文档协作

本地独立编写的短流程；借鉴协作分阶段的设计思想，没有复制未附独立许可证的 doc-coauthoring 正文或引入其 Claude 工具接口。

## 根据任务推进

1. 从用户已给出的材料确定读者、文档目的、输出形式和现有模板。只询问影响结论的缺口，不固定要求回答一长串问题。
2. 先组织最关键的内容：用途、约束、操作、结果或决策依据；简单修改直接改目标段落，不为小改动重建整篇文档。
3. 起草与事实分开：引用真实代码、命令输出或用户提供的数据，说明适用版本和限制。示例标为示例，不把旧测试结果当成当前验证。
4. 从首次阅读者角度检查：术语是否定义、路径和命令是否存在、前置条件是否齐全、失败后如何继续、结论与证据是否对应。
5. 交付可用正文和确有必要的未验证项；用户可直接编辑文件，不要求所有修改都经过聊天转述。

只要求审阅时提供意见，不自行创建文件或执行文档命令。写文件仍用已有审批，保留用户改动；不自动发布、提交、分享内部资料或上传到外部服务。

独立读者验证仅在用户需要、宿主确有合适工具且范围获授权时进行；不能用科研/测试子 Agent 冒充通用文档读者，也不要求另开 Claude 会话或新增压缩/记忆系统。
需要 Word/PDF/PPT/表格文件时按实际交付格式加载对应技能，普通 Markdown 文档不同时加载四个 Office 技能。
