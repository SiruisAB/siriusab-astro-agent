# 浏览器验收

本地工作流程，吸收 Anthropic webapp-testing 的“观察真实页面后再操作”思路；不引入其自动管理服务脚本。

先确认现有服务地址、实际页面和可用浏览器工具。只读诊断不修改项目；需要启动临时服务或执行脚本时沿用工作台审批，不能停止/重启已有服务以便测试。

有浏览器工具时使用隔离配置，读取已渲染 DOM/可访问角色后选择元素；先验证状态与交互，再截图。页面包含 SSE/WebSocket，`networkidle` 可能永远不到；用明确可见元素、请求完成条件或状态标记，并给等待设置合理超时。

优先验证这次改动涉及的交互，不为小改动搭完整测试框架。保存模型设置、修改会话或发送消息属于有副作用的动作，应使用临时工作区和假服务；不把真实 Key 放入录屏、截图、日志或浏览器脚本。

检查窄屏菜单、对话滚动、长工具输出、设置表单、审批按钮、焦点与错误信息。报告实际运行的工具、测试范围与未验证项，不把静态 DOM 检查叫作完整 E2E。

本项目已按用户要求移除测试文件。未经新的测试编写请求，不恢复 `tests/` 或历史验收脚本；这次任务必要的临时验证放项目外临时目录，结束后只清理自己创建的明确路径，不清空项目、浏览器用户目录或会话数据库。
