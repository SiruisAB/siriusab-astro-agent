# 版式与 OOXML 注意事项

本地适配说明，参考 Anthropic PPTX 技能；库行为须核对所用版本。

## 创建

`pptxgenjs` 在添加页面前设置布局；不要把 10×5.625 英寸画布误当成宽屏 13.3×7.5。颜色通常是无 `#` 的六位 HEX，透明度使用专门属性；阴影偏移不能用负值。每个添加操作使用独立选项对象，库可能就地转换单位。

文本框内边距会影响对齐；明确页面范围、内容区和文字层级，不依赖单纯缩字号解决过载。讲稿使用 notes，不放到可见文本框。列表使用库提供的项目符号，不写字面 `•`。

需要可统一换主题的较大新建文稿时，使用主题、布局、命名占位符和章节。`defineSlideMaster` 在库中实际创建布局；不要把布局称为新母版。图表轴、组合图和数据标签可产生无法打开的 OOXML，需要实际校验，不仅检查文件存在。

## 已有文件

PPTX/POTX 是 OOXML ZIP；外来文件先检查包路径、链接和大小预算，再处理临时副本。新增/删页/改序先完成结构操作再改内容；关系、内容类型、页序列表必须同步。

`scripts/add_slide.py` 在 `.pptx` 模式中应明确 `-o` 新文件，不然可能原地写入；复制页面可能共享图表或嵌入对象，修改其中之一可能影响另一页。
`scripts/clean.py` 会删除不再引用的部件，只能对已经确认的临时副本使用，不能清理用户项目或原文稿。

用 `python-pptx` 修改时，整体赋值 `text_frame.text` 会损失 run 格式；仅改所需 run。底层 XML 编辑须保留命名空间、关系、动画与媒体，不随意重排根元素。

结构校验、文本提取和图片渲染检查的是不同层面；模板的原有错误需和新增错误区分。缺少验证工具时保留未验证项，不能用“能被 python-pptx 打开”推断 PowerPoint 一定可用。
