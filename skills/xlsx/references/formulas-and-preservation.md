# 公式、缓存与原文件保护

本地适配说明，参考 Anthropic XLSX 技能；计算函数兼容性取决于实际 Excel/LibreOffice 版本。

- `load_workbook(data_only=True)` 读取缓存，不保留公式；不要保存这个实例覆盖含公式的源文件。另用默认加载读取公式。
- openpyxl 写公式后通常没有计算缓存；`None` 可能表示尚未计算，也可能是空结果，不能直接判为错误。
- 合并区域只写左上角；含空格的跨表引用须加引号。日期、百分比、计数和坐标须设置正确格式并核对实际存储单位。
- `.xlsm` 修改需要 `keep_vba=True`，但保留 VBA 不等于允许执行宏。富文本、文本框、形状、切片器等不一定能由常规保存完整保留，先检查并告知风险，必要时只改目标 XML 副本。
- 不盲目禁用所有新函数；先确认接收方计算引擎和验证能力。兼容性不足时使用等价函数或明确需要 Excel 重算，不把公式改成伪造常量。

`scripts/recalc.py` 输出 JSON；`errors_found` 可能仍退出 0，必须检查 `status`、`total_errors`、`error_summary`、`not_computed` 和顶层 `error`。保留的缓存可能过时，绿色求值也不证明行范围/公式逻辑正确。

用已知输入抽查关键公式、单位和误差传播。与原文件比较才能区分旧问题和新增问题；没有执行重算时写明未验证，不用清理缓存或假数据掩盖错误。
